# RPG Tracker — обновление дизайна и просмотр изображений

Это дополнение к **работающему** RPG Tracker из предыдущего архива. Никаких изменений схемы Supabase, SQL-функций или переменных окружения не требуется.

## 0. Сначала сделайте резервную копию

1. Остановите локальный сервер `Ctrl+C` в терминале VS Code.
2. Скопируйте всю папку `rpg-tracker` в отдельную папку `rpg-tracker-backup`.
3. Если вы меняли исходники после предыдущей версии, **сравните файлы перед заменой**: ZIP заменяет файлы с совпадающими именами. Изображения и данные Supabase ZIP не изменяет.
4. Файл `.env.local` оставьте на месте: в архивах его нет.

## 1. Как применить обновление

### Вариант А — минимальное обновление (рекомендую)

Распакуйте `rpg-tracker-design-patch.zip` **в папку, внутри которой лежит каталог `rpg-tracker`**. Подтвердите замену файлов. ZIP содержит папку `rpg-tracker/src/…` и только изменённые исходники и документы.

Если вы используете PowerShell и архив лежит, например, в `Загрузки`, можно вместо интерфейса проводника выполнить команду **из родительской папки вашего проекта**:

```powershell
Expand-Archive -Path "$HOME\Downloads\rpg-tracker-design-patch.zip" -DestinationPath "." -Force
```

Проверьте путь: у вас должен получиться `rpg-tracker/src/components/CharacterPortrait.tsx`, **а не** `rpg-tracker/rpg-tracker/src/…`.

### Вариант Б — полный проект

`rpg-tracker-design-full.zip` содержит все исходники предыдущей подготовленной версии вместе с новым дизайном, но без `node_modules`, `.next`, `.env.local` и пользовательской базы данных.

Распаковывайте его в отдельную папку и переносите свой `.env.local` из рабочей версии вручную. Для уже работающего сайта предпочтительнее вариант А.

## 2. Как запустить после замены

Откройте `rpg-tracker` в VS Code и выполните:

```powershell
npm run lint
npx tsc --noEmit
npm run build
npm run dev
```

Если зависимости отсутствуют, перед этим выполните `npm ci`. После запуска откройте `http://localhost:3000`.

## 3. Какие экраны изменились

- `/` — каталог одобренных персонажей: компактные портреты, поиск по имени, сортировка, читаемые HP и броня.
- `/dashboard` — заявки и собственные персонажи: компактные изображения и аккуратная форма.
- `/character/<id>` — досье персонажа: портрет, показатели, три колонки карт и журнал событий.
- `/admin` — очередь модерации и таблица персонажей с миниатюрами.
- `/admin/characters/<id>` — управление здоровьем/бронёй и картами с единым оформлением.
- `/login` — вход и регистрация в том же стиле.
- Общая шапка — адаптивная навигация.

## 4. Увеличение изображений

Нажмите на любую миниатюру. Откроется затемнение поверх страницы, а картинка будет показана целиком (`object-contain`), без обрезки.

Закрыть можно:

- клавишей `Esc`;
- кнопкой `×` в правом верхнем углу;
- щелчком по затемнённому пространству вне окна изображения.

При открытии окна прокрутка страницы блокируется, после закрытия фокус возвращается на миниатюру.

## 5. Почему теперь не сливается журнал

Раньше «Урон: 7» и дата могли оказаться вплотную в одной строке. Теперь запись состоит из блока:

1. цветная иконка типа действия;
2. жирное название и количество;
3. отдельно стоящая дата и время (на узких экранах — следующей строкой);
4. отдельные компактные поля `HP 30 → 23` и `Броня 0 → 0`;
5. комментарий, если он есть.

## 6. Проверки после обновления

1. В общем списке видны **маленькие** изображения. Нажмите на миниатюру, увеличьте и закройте её через `Esc`, `×` и клик по затемнению.
2. В личном кабинете и админке проверьте то же самое.
3. Откройте профиль персонажа, проверьте три колонки карт, HP/броню, журнал действий на телефоне и компьютере.
4. Зайдите как игрок и как администратор. Создайте заявку, одобрите её, нанесите урон, восстановите здоровье, добавьте карту — механика должна работать как раньше.
5. Откройте два браузера и проверьте автоматическое обновление характеристик.
6. Убедитесь, что картинки отображаются из Supabase Storage, а не только из кэша разработчика.

## 8. Важные оговорки

- Сборка TypeScript и проверка ESLint выполнены в рабочей среде и прошли. CSS синтаксически компилируется.
- Полный `next build` не удалось закончить **в этой среде**, так как нужны Linux-бинарники Next.js, а доступ к npm недоступен. На вашем Windows-компьютере выполните `npm run build` перед деплоем.
- Реальные аккаунты и база Supabase здесь не подключались, поэтому живой пользовательский тест остаётся за вами.
- Новый дизайн основан на исходниках из предыдущего ZIP. Если вы редактировали их после прошлого этапа, не заменяйте файлы без сравнения.

**Новые пакеты ничего не изменяют в базе данных. Не запускайте повторно SQL из предыдущих этапов ради установки дизайна.**
